## What the simulation does establish

* The I2C and SPI conversations are correct and within the chips' timing limits: register numbers, command words and frames, start and stop conditions, acknowledges.
* Device behaviour as modelled from the datasheets: MCP23017 registers, MCP3008 3-byte read (including the null bit), MCP4822 16-bit command word, MCP7940N oscillator start and BCD time with minute and midnight rollover, 24LC512 16-bit addressing, 128-byte pages and the 5 ms busy time.
* Button handling (one action per press, bounce and long holds), dice faces, bar graphs, fault codes, and a counter that survives several simulated power cycles.
* Pin configuration values (for example `CLKDIV`, `AD1PCFG`, `TRISx`) are what the pages describe.

Deliberately broken copies of the code were run through the tests (wrong addresses, swapped bytes, missing pull-ups, no edge detection, inverted logic, missing waits and so on). Each real fault was caught. A handful of "equivalent" mutants (a change with no observable effect, such as masking a bit that is always zero) are not counted as misses.
